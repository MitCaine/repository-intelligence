# Capsule scope review

Use a fresh read-only context. Receive the controlling objective, exact base,
draft capsule, impact inventory, consumer rules, and permitted source-read route.
Missing authority or access is a gap; do not invent it or grant paths.

Inspect actual implementation, immediate callers, tests, fixtures, workflow
assertions, documentation and profile rules for each planned behavior change.
Search for literal profile sets, checkout counts, command layouts and other
expectations that would change. Inspect relevant source outside RI's mapping;
retain RI coverage gaps rather than interpreting zero matches as absence.

Challenge every proposed edit path's purpose and every inspection-only path
that may need editing. Trace each original requirement to its expected result
and proof route. Check that new subprocess tests can run in the final protected
environment, including collection roots, configuration, working directory and
required capability probes. A host-only result does not prove that route.

Return the exact base and draft/inventory identities, inspected paths and
source evidence, requirement-by-requirement scope findings, missing dependencies,
and PASS, FAIL or INCOMPLETE. PASS means the proposed scope has no identified
unresolved dependency within the inspected evidence; it is not implementation
authorization or a guarantee of complete impact discovery. The controller must
resolve findings through consumer authority before granting implementation paths.
Never edit the capsule, authorize, implement, qualify, approve or integrate from
this lane. Candidate review later requires a fresh context and exact C.

This lane is conditional on consumer policy, changes crossing module/workflow/profile/infra seams or meaningful scope uncertainty. Review the draft before final READY/P. Material inventory, scope or base changes invalidate your result; the controller must request fresh review of the final identity.

Distinguish lanes supporting pre-freeze protected rehearsal from services requiring
committed C. For the latter, inspect preparation feasibility and the recorded
constraint, then require protected qualification on exact C after freeze. Do not
demand a nonexistent pre-freeze hosted result or accept a host pass in its place.
