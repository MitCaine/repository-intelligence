## Implemented findings

- **False Rust completeness:** a file containing invalid UTF-8 in a comment
  could report `navigation_only`, unlike the other non-Python adapters. Rust
  now validates UTF-8 before extracting declarations. Invalid source retains
  its raw byte identity but produces an incomplete mapping and no successful
  inventory delta. Valid non-ASCII Rust remains supported.
- **Missing planning coverage:** candidate exclusions already blocked apparent
  removals, but planning exclusions did not block apparent additions. Both
  directions now check exact file paths and their parent directories. A new
  `planning_coverage_missing` mismatch prevents interpreting an unobserved
  baseline as absence. Unrelated exclusions and sibling path prefixes remain
  compatible. Ancestor-set lookups also replace the files-by-exclusions scan.
- **Diagnostic overhead:** the syntax probe walked every node even in a clean
  tree. It now skips subtrees with no Tree-sitter error flag. Callable mapping
  still traverses the source independently. Full-walk parity regressions cover
  every pinned grammar/suffix, including missing tokens and truncated details.
- **Workflow and documentation drift:** added standalone `AGENTS.md`, replaced
  a stale issue-based inventory pointer with the implemented contract, corrected
  the claim that observed exclusions never affect compatibility, updated the
  current version references, and relabeled already-corrected audit findings.
- **No automated baseline:** added a read-only, exact-action-revision-pinned
  GitHub workflow for macOS 15 / Python 3.12 and 3.13. It derives wheel requirements
  from `pyproject.toml` and requires the installed-consumer test during discovery.
  Hosted execution remains unverified until the workflow is pushed and runs.

Language semantics stay in their existing adapters; acquisition, diagnostics,
ranking, and comparison retain their existing interfaces. No additional runtime
dependency, daemon, semantic provider, or consumer permission policy was added.
Upstream [Tree-sitter node error flags](https://tree-sitter.github.io/py-tree-sitter/classes/tree_sitter.Node.html#tree_sitter.Node.has_error)
provided the diagnostic optimization; it was verified against RI's pinned
0.25.0 runtime. [setup-python](https://github.com/actions/setup-python) and
[checkout](https://github.com/actions/checkout) provide the CI environment and
checkout. Their v7 commit references were verified directly before pinning.

## End-to-end edge-case follow-up

A further pass reproduced and corrected failures across acquisition, syntax,
identity, optional native analysis, comparison, and context-page preparation.
The earlier counts/contracts above remain historical; the integrated follow-up
uses navigation **6**, inventory **13**, adapter/mapping **10**, and separate

### Reproduced corrections

- CR-only Python, Java, and C/C++ comments could hide declarations while the
  packet still reported successful navigation. JavaScript/TypeScript and C#
  could expose incorrect lines. Width-preserving parse-input normalization now
  follows each language, retaining original source bytes and hashes. Rust/Go
  keep their LF-based line semantics; their lone-CR display columns were fixed.
- Python's second-line encoding cookie was missed with CR-only physical lines.
  Native AST header lookup also failed for valid Unicode-normalized identifiers.
  Both providers now use the physical-line encoding rules and normalized names,
  with raw signature spelling and byte envelopes preserved.
- Distinct C# explicit-interface accessors/events, generic type owners, and local
  helpers under getters/setters/operators could collide. JS/TS getter/setter
  helpers and C++ local-class methods under overloaded functions had similar
  collisions. Harmless comments produced apparent removals/additions. Owner
  discriminators now preserve the relevant syntax and stable named deltas.
- Directory queries discarded module-binding evidence and raised for roots
  containing only excluded source. Their packets now preserve both observations,
  including when the query has no callable matches.
- Native Rust syntax JSON omits parser diagnostics. Three malformed fixtures
  produced zero ERROR nodes; the legacy count now explicitly reports its
  lower-bound coverage in JSON and compact text. No extra parser is substituted
  for native validation.
- Native Rust definition queries inherited analyzer-only test/Miri defaults.
  Live fixtures selected the wrong configuration's declaration. V2 explicitly
  sets test mode (default false) and empty extra Cargo cfg overrides; tests check
  the exact normal/test/Miri-selected targets. Discovered toolchain cfg remains
  intact. This is still analyzer evidence, not compiler-build equivalence.
- Native Rust's position validation treated lone CR as a newline while the
  analyzer did not. LF, CRLF, lone CR, Unicode/UTF-16, multiple LocationLink
  targets, escaped filenames, and an empty final line now have direct coverage.
- The earlier LF-counting Poker page recipe could generate a mechanically valid
  excerpt that omitted a function's last line when a preceding comment contained
  a Unicode separator. The current recipe follows the consumer's actual line
  splitting and checks that the full declaration bytes are inside the excerpt.

### Primary-source checks

The investigations used the pinned installed grammars and live analyzer
`1.97.1 (8bab26f4 2026-07-14)`, alongside these upstream contracts. Rolling
upstream documents describe the checked date, not a pinned provider guarantee.

- [Python lexical rules](https://docs.python.org/3/reference/lexical_analysis.html)
  specify physical newlines, encoding cookies, and NFKC identifier normalization.
- [ECMAScript line terminators](https://262.ecma-international.org/5.1/#sec-7.3),
  [Java physical lines](https://docs.oracle.com/javase/specs/jls/se25/html/jls-3.html#jls-3.4),
  [C# line terminators](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/lexical-structure#632-line-terminators),
  and [GCC initial processing](https://gcc.gnu.org/onlinedocs/cpp/Initial-processing.html)
  support the CR handling. Local Clang preprocessing independently confirmed
  the C/C++ comment boundary. Rust/Go were deliberately tested separately.
- [C# explicit-interface members](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/interfaces#1962-explicit-interface-member-implementations)
  include properties, indexers, and events as well as methods.
- [Native Rust parse implementation](https://github.com/rust-lang/rust-analyzer/blob/master/crates/rust-analyzer/src/cli/parse.rs)
  serializes the syntax tree without its parse diagnostics.
- [Analyzer configuration](https://rust-analyzer.github.io/book/configuration.html),
  [cfg conversion](https://github.com/rust-lang/rust-analyzer/blob/master/crates/rust-analyzer/src/config.rs),
  and [workspace construction](https://github.com/rust-lang/rust-analyzer/blob/master/crates/project-model/src/workspace.rs)
  explain implicit test/cfg defaults and why empty overrides preserve discovered cfg.
- [Rust whitespace](https://doc.rust-lang.org/reference/whitespace.html) and
  [analyzer line indexing](https://github.com/rust-lang/rust-analyzer/blob/master/lib/line-index/src/lib.rs)
  distinguish lone CR from LF. [LSP LocationLink](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/types/locationLink.md)
  separates the selected name from a whole declaration; a target range is not
  automatically an adequate context page.
