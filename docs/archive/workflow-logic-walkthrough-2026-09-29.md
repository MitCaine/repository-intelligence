## Fresh controller

| Step | Inputs and responsible actor | Required transition |
| --- | --- | --- |
| 1. Orient | Controller reads consumer authority/commands and RI routing/setup. | Resolve actor/command/publication map, runtime, review format and completion capability. No P/C required yet. |
| 2. Intake | Authenticate issue/objective, base, worktree, planning grants and retained active state. | Keep every original requirement and identify unresolved authority. |
| 3. Draft | Planner receives sourced intent, exact base and bounded planning grants. | Return draft/inventory identities and gaps, not authoritative P. |
| 4. Scope | Controller records conditional challenge trigger or omission rationale. | Challenger reviews exact draft/inventory/base when required. Planner revises findings; material changes invalidate verdict and require rechallenge. |
| 5. Final planning | Planner finalizes READY/P through consumer-authorized planning route. | Controller verifies P, complete objective trace, final inventory, applicable challenge, runtime probe, commands and planning checks. |
| 6. Dispatch | Controller supplies frozen capsule/P, permitted context and checks. | Preflight checks implementation phase only; no future C required. |
| 7. Implement | Implementor edits/tests within grants and returns changes/status. | Controller checks actual worktree diff/scope; C is returned only if implementor has capture authority. |
| 8. Capture | Authorized consumer actor captures C after applicable precommit checks. | Controller authenticates exact C and full P..C; publish only at the mapped stage. Poker reviews captured C before publication. |
| 9. Qualify | Frozen checks and accepted host/source lane apply to C. | Pre-freeze rehearsal where available; committed-C-only protected qualification after freeze. Bind profiles, collection, skips, logs, modes/bytes and actual tested source. |
| 10. Wait | External jobs use verified callback/watcher; native agents use native completion. | Prepare bounded independent work, then wait; no repeated unchanged status checks. Logs remain outside clean candidate checkout. Cleanup uncertainty blocks overlapping retries. |
| 11. Review | Fresh enforced read-only reviewer gets C/Q, full diff, capsule and accepted report requirements. | Return all-AC/standards dispositions and importable consumer evidence. Published C required only by that lane. |
| 12. Correct | Controller authenticates findings and remaining allowance/lineage. | Preserve failures; repair within grants/budget and requalify/re-review changed C, or replan through authority. |
| 13. Integrate | Matching exact-C proof, review, approval and current refs. | Consumer guarded publication/acceptance controls integration. No skill or role grants acceptance. |
| 14. Close | Verify history/schema, required installed probes, integrated result and issue state. | Retrieve reviewed/failed source and evidence; synchronize primary safely, reconcile issue/review and prune only unused completed refs. |

## Established controller

Resume begins with the retained checkpoint and live Git/runner reconciliation,
not step 1's new capsule creation. Re-read current authority and installed role
instructions. Verify revisions, current stage, B/P/C where applicable, active
job/destination, Q/R/approval, findings, remaining allowance and next action.
An active job continues through its verified completion route; a completed job
is not restarted to recreate notification. An exhausted allowance stays exhausted.
For revised rules, compare permissions, commands, proof and formats at a safe
boundary; preserve jobs/records and revalidate only affected readiness/evidence.
Pure wording changes do not automatically require reruns. Return to the actual
phase above without inventing future artifacts or treating missing proof as PASS.
