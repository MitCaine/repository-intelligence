# Capsule independent review

Resolve and read the selected **independent reviewer** document through the
[role locator](references/project-procedure.md). Do not read the full controller
procedure as reviewer orientation.
Review the exact candidate or no-change source, bounded task, full diff, relevant
tests/results and applicable repository standards. Use direct source and ordinary
logs; RI navigation/comparison is supporting evidence, not a substitute for review.

Check affected current documentation, examples and links for stale or contradictory
instructions; historical records remain explicitly historical.
Remain read-only. Cover each acceptance criterion and applicable standard with a
concise evidence-backed disposition. Separate actual defects from missing evidence
and uncertainty; identify concrete paths/cases for corrections. Do not demand a
separate verdict per RI declaration, custom report schema or retrieval transcript
unless a separately adopted project requirement genuinely needs one.

The candidate's author/implementor cannot review it. Fresh context is default;
last-resort capacity reuse may use an uninvolved idle agent, recording that fact.
A reused verdict is not a new review. No nested agents, tests or source writes as
part of this read-only review; request existing evidence through the controller.

Return PASS, findings or unresolved gaps with candidate identity and supporting
evidence using the host's normal handoff. Missing required evidence cannot pass.
Controller integration is separate; review does not grant merge authority.
For explicitly post-installation criteria, review the implementation and planned
check now; identify proof still due before closeout. Do not require installation
proof before the approval needed to install. Missing evidence already due at the
review stage remains a blocker.
