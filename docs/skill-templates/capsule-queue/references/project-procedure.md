# Selected role instructions

> **Defunct project — historical reference only.** RI is no longer developed or maintained.
> See [project status](https://github.com/MitCaine/repository-intelligence/blob/main/README.md#project-status). Instructions and commands below describe the retained snapshot,
> not an actively supported workflow; existing pinned consumers retain their own authority.


Resolve instructions through the controller’s authenticated handoff and the
consumer project-root `docs/local_project_map.md`, not this installed folder.
The controller supplies the selected RI revision, role-skill folder and common-contract location/identity,
applicable project requirements and task inputs permitted for the selected role. Verify those resources
are readable; never silently substitute newest RI main or a different role.

Controllers read the selected Start an issue procedure. Builders, implementors
and reviewers read their selected authoritative role skill and its locator, plus
Shared worker rules in the selected `docs/worker-instructions.md` in full,
not the full controller procedure or unrelated project orientation. Optional
helpers operate within the caller’s assigned role; they grant no new authority.
If an older selected version lacks the selected worker instructions, report that adoption gap to
the controller rather than silently changing instructions during the attempt.

This relocatable locator contains no copy of workflow rules. At installation,
verify actual role resources through the consumer’s supported route. Copying a
skill folder alone does not supply the selected instructions.

## Waiting and recovery

For a controller or assigned external watcher, resolve only the selected
procedure’s waiting/recovery sections through the handoff/map. Other workers use
their role’s bounded diagnosis and terminal handoff instructions. Read the
relevant section, not the entire controller orientation.

For bounded reads, use the map/handoff-selected section reader under its
workflow-tools contract when available. Select only role-permitted inputs and
check identity/coverage; resolve incomplete output through the governing role rule.
Ordinary reads remain supported.
